## 2. 总体背景与目标

- 项目为什么开始：将计算机与生物学知识结合，解决“调控序列如何共同决定表达量”的实际建模问题，并让生物设计者通过自然语言使用计算工具。个人学习动机为合理归纳，准确的立项契机仍待用户补充；仓库明确的目标是 BioE234 场景下的预测型 MCP server。
- 面向的用户、研究问题或业务问题：面向合成生物学学习者、实验设计者及需要选择调控元件组合的研究人员；研究问题是启动子转录信号、RBS 翻译信号与起始区 RNA 上下文是否能共同预测表达，并在未见元件上保持有效。
- 当时的目标：完成“真实数据 → 可解释特征 → 训练模型 → 预测/排序 → LLM 调用”的闭环；后续将科学问题细化为总蛋白预测与稳态 `protein/RNA` 翻译 proxy 预测，评估结构特征的独立增益。
- 成功标准：初始 SPEC 要求有效数据超过 10,000 行、模型可保存、Spearman >0.3、测试通过、MCP 正常启动、跨工具演示可调用至少两个工具、不同启动子产生不同 RBS 排序；后续路线图增加严格元件留出、同条件基线、消融、组 bootstrap、分组重要性和误差记录。当前结果支持实现与评测闭环，不能据此推导实际实验筛选成功率。
- 约束：主体周期约 3 个月；本地计算环境与 RNA 折叠开销；公开数据只覆盖一个 reporter/特定实验语境；测量 TSS 可用性；精确质粒 CDS 访问受限；模型目标与真实业务单位不同；个人承担端到端实现。硬件型号、预算与总工时未知。
- 关键利益相关者：用户本人；提供方法反馈的教授；未来使用预测/排序工具的实验设计者。没有实际企业客户、临床科室、药企采用或付费用户证据。

## 3. 项目结构与工作流

- 系统/研究流程概览：离线训练与评测、在线工具调用两条流程共享序列特征模块。

```text
Kosuri 三张 XLS 表
  → 清洗引号、按原作者 bad.prot/bad.RNA 标记过滤、关联 promoter/RBS
  → 保留实测 TSS，构建 TSS→AUG→暂定 sfGFP 早期 CDS 的 RNA 上下文
  → 9 个序列/间距特征 + 3 个结构可及性特征
  → XGBoost 回归；与常数、元件效应、Ridge、OSTIR 等方法比较
  → 随机/启动子留出/RBS 留出/双新元件：固定 holdout、5 折、组 bootstrap、4 seeds
  → 逐构建预测、指标、归因和残差报告

自然语言请求
  → Gemini 客户端发现 MCP 工具并读取模块技能说明
  → 序列评分 / 表达预测 / 遍历 111 个 RBS 并排序
  → 工具结果回传 → 语言模型组织解释与候选建议
```

- 输入：启动子、RBS DNA 序列；可选实测 `tss_best`；离线输入 `sd01.xls/sd02.xls/sd03.xls`、暂定 90 nt sfGFP FASTA、训练/验证配置。
- 关键处理或决策节点：区分非转录 promoter DNA 与实际 RNA；确定 ATG 只拼接一次；分离序列预测模型与已测元件 oracle；避免同一元件身份跨训练/测试；OSTIR 缺失评分显式保存并取共同可评分样本；所有校准/调参仅使用训练折。
- 输出：表达点预测、使用的特征及上下文可用状态；RBS top-N 清单；Parquet 数据、CSV/JSON 评测结果和三类现有分析图；模型持久化代码。
- 使用者或下游去向：可用于实验候选优先级排序与教学演示；没有实际候选被合成、生产滴度提高或实验成本下降的证据。
- 我所在的 workstream：独立承担全部计算流程，详见第 4 节；数据生产方和 course starter 的贡献另行保留。
- 支撑：[数据管线](../modules/pipeline/pipeline.py)、[特征模块](../modules/features/features.py)、[模型模块](../modules/model/model.py)、[MCP server](../server.py)、[Gemini client](../client_gemini.py)。

### Workstream：生物机制特征工程与表达回归

- 触发原因或具体问题：仅独立分析启动子/RBS 序列难以覆盖上下文作用；历史 promoter-tail MFE 会把部分非转录 DNA 当作 RNA，并遗漏下游 CDS。
- 我的职责：将转录与翻译知识转成可计算、可测试的特征，并建立可解释的回归和排序能力。
- 我实际完成的行动：构建 motif 匹配、GC、spacer/SD 间距等 9 个基础特征；用实测 TSS 和早期 CDS 计算 SD/start 未配对概率以及 SD-to-start opening ΔG，形成 12 特征 B6；保留旧 MFE 仅作对照；实现 XGBoost 训练、评估、表达预测和 RBS 排序。
- 技术/方法选择及理由：约万级表格数据、低维特征适合树模型；XGBoost 捕捉非线性与特征交互，Ridge 提供线性对照。RNA 可及性采用 partition function ensemble 与硬约束开放能量差，而非单一全局 MFE。

### Workstream：泛化评估、基线与可复现统计证据

- 触发原因或具体问题：随机行拆分会共享 promoter/RBS 身份，容易把组合插值效果理解为新元件泛化；单一 Spearman 缺少误差、机制对照与不确定性。
- 我的职责：建立与真实设计场景匹配的评测，并证明结构改进是否可重复。
- 我实际完成的行动：实现四类固定 holdout 和四类五折拆分；构建 B0/B1/B2/B3/B4/B6 对照，引入 OSTIR 和同特征 Ridge；Ridge 在外层训练折内做 3 折分组调参；对共同 OOF 预测做 1,000 次组 bootstrap；重复 42、7、123、2026 四个外层 seed，保存折分配和逐构建结果。
- 技术/方法选择及理由：按 promoter/RBS 分组对应未见元件使用场景；双新元件同时隔离两类 ID；配对比较统一样本、目标与外层折，避免不同数据集造成虚假优势；对相关组合采用组重采样。
- 直接产出：单 seed 260 条 fold 指标、176 项 bootstrap 指标/配对差、完整 OOF 表；四 seed 1,040 条 fold 指标与汇总表；各 seed 运行元数据与无身份泄漏测试。
- 观察到的结果：在 11,672 个共同可评分构建上，B6 相对 B4 的翻译 proxy Spearman 与 log-MAE 在三个生物留出中均改善，seed42 配对 95% CI 不跨 0，且 4/4 个 seed 保持方向。双新元件场景不能证明 B6 优于 Ridge 或 OSTIR。
- 后续复用、采用或影响：可作为新增模型/新数据的统一实验协议；没有独立外部数据验证或论文发表证据。

- 系统架构或 pipeline：三层数据/特征/模型模块；JSON 配置驱动 MCP 注册；本地 CLI 客户端进行工具编排。评测脚本与产品训练入口分别维护。pipeline 当前依赖 features 的上下文函数，因此不沿用旧 SPEC“pipeline 完全独立于 features”的架构描述。
- 数据来源与处理：三张 Kosuri 2013 补充 XLS，promoter/RBS 表为已处理的元件测量；构建表具有 protein、RNA、计数、标记与原论文 model 列。本项目清洗并复用标签，没有重做原始测序比对/表达定量。`deltaG` 留在数据表，但当前 B6 `FEATURE_COLS` **未使用**；`mean_RNA/mean_xlat` 只进入明确的已测元件 oracle，对新元件不可用。
- 实验/评估设计：产品默认预测原尺度 `prot`，按 5 个表达分位 stratify 为 80/10/10，300 棵树、深度 5、学习率 0.05、subsample/colsample 0.8；验证集用于传入 eval_set，未见 early stopping 或训练内搜索。严谨 benchmark 则预测自然对数 `log(prot)`、`log(RNA)`、`log(prot/RNA)`；后续 grouped CV 只保留总蛋白与翻译 proxy 两个目标。二者是不同训练目标/协议，benchmark 的 log 模型分数不能自动视为默认 API 模型分数。
- 基线与消融：固定 holdout 为 B0 训练中位数、B1 one-hot 元件身份的加性 Ridge、B2 已测元件 oracle、B3 历史 MFE、B4 9 个序列特征、B6 12 个序列+可及性特征；后续五折为 B3/B4/B6 的 XGBoost 与 Ridge，加 B7 OSTIR（仅翻译 proxy）。路线图另列 B5，但实际未作为独立方法输出；不能称“B0–B7 八种方法全量完成”。
- 质量控制、测试或复现机制：序列字母表、TSS 坐标、ATG/CDS 边界、RNA 概率范围、开放能量数值回归、split 身份隔离、Ridge 内层无泄漏、OSTIR 缺失处理、置换单位一致性、配对残差和多 seed 汇总均有测试。模型接口 smoke 使用固定 600 行样本，测试集约 60 行。最新阶段 9 日志记录 **64 passed / 21.34 s**；此前阶段 8 为 65 passed，旧 README 的 29 tests 已过时。本次采集未运行 pytest/训练/benchmark，以满足只读及单文件输出限制。
- 复现信息：seed42 五折、bootstrap seed43、1,000 次；split 稳定性另用 7/123/2026，XGBoost 训练 seed 固定42；Ridge alpha 25 个 logspace 值 `1e-5…1e7`，训练内 3 折，按 log-MAE 选择。运行命令已记录在 summary，包括 `scripts/biological_benchmark.py`、`scripts/run_ostir_baseline.py --threads 4`、`scripts/grouped_biological_validation.py --folds 5 --bootstrap-replicates 1000 --random-state 42`、置换与残差脚本；此处仅记录，不执行。

## 7. 关键事件与判断

以下按 STAR 组织为备用面试故事。第一人称行动归属依据用户“纯个人项目”，具体决策时间来自阶段日志；个人当时的想法、教授互动细节仍可在末尾问题中补充。网页材料是同类难题参考，不代替个人经历证据。

### 事件：把“RNA folding 特征”修正为真实转录起始区可及性

- 情境与相关人员（S）：初版已完成表达预测与工具化，教授认可模型有真实数据与生物特征，但指出结构输入缺少 RBS–CDS junction 和早期 CDS。
- 困难、冲突或不确定性：promoter DNA 不是完整转录本；全局 MFE 不直接等于核糖体入口可及性；实测 TSS 和精确 reporter CDS 来源必须交代。
- 我的责任（T）：使模型输入与生物机制对应，同时保持原有预测/排序接口可用。
- 我的行动（A）：阅读补充表的 TSS 语义，保留坐标与置信度；重建 TSS 至 AUG 的 RNA 并拼接不重复的早期 CDS；用 BPP/partition function 和硬约束能量差替换单一 MFE；增加坐标、概率、开放能量回归测试，并将无法核验的 CDS 标为 provisional。
- 为什么这样决策：优先修正生物输入与任务定义，再比较算法，避免将机制不正确的特征通过复杂模型包装成强解释。同行项目也面临邻近序列改变 5′UTR 表达行为的问题；本项目采用固定 reporter 的工程特征方案是自己的实现选择。参考：[跨序列上下文表达预测研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC11260469/)。
- 结果（R）：B6 对 B4 在三类严格生物留出中翻译 proxy log-MAE 降低约10%–13%，配对组CI不跨0，四seed方向一致；精确质粒CDS核验仍未完成。
- 复盘、改进或后续变化：公开暂定参考的边界；新序列缺少TSS的产品场景需要独立评估；原实验30°C与结构计算37°C也值得做参数敏感性检查。
- 可体现的能力：领域知识转计算特征、接受专家反馈、定义数据契约、实验消融和证据管理。证据：[教授反馈](professor_feedback_status.md)、[阶段1–4](biological_modeling_stage_log.md)、[特征实现](../modules/features/features.py)。

### 事件：不再用随机拆分高分代替新元件泛化

- 情境与相关人员（S）：组合矩阵重复使用相同 promoter/RBS，初始训练入口采用随机80/10/10；用户希望工具预测新设计，教授要求更困难拆分。
- 困难、冲突或不确定性：随机行测试中两类元件通常已在训练中出现；双新元件需同时隔离两个交叉因素，不能只换一个split参数。
- 我的责任（T）：让报告清楚回答“已见组合插值”和“未见元件外推”分别能达到什么效果。
- 我的行动（A）：实现promoter/RBS整组留出与double-unseen；将触及任一测试ID的行排除出训练、测试只取双留出交集、交叉组合标unused；保存固定折和逐构建预测；Ridge调参仅在训练内同类型分组；对组而非相关行做配对bootstrap，并重跑四个外层seed。
- 为什么这样决策：验证单位应匹配部署时的新实体。官方交叉验证文档指出依赖样本组不满足独立同分布假设，宜按组验证；本项目据此类原则结合自身交叉矩阵结构制定方案。参考：[scikit-learn 分组交叉验证](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)。
- 结果（R）：得到完整四场景评测；总蛋白随机ρ0.896在双新场景降至0.542；结构改进仍有收益，但XGBoost并未在双新条件下稳定胜过Ridge/OSTIR。
- 复盘、改进或后续变化：保留较弱结果并区分同数据重分组与外部复现；双新seed42只有2,337个OOF组合，不能声称所有11,672行均经过该外推测试。
- 可体现的能力：识别验证偏差、设计复杂拆分、训练测试隔离、统计严谨性与如实界定模型边界。证据：[grouped validation](../scripts/grouped_biological_validation.py)、[split测试](../tests/test_grouped_biological_validation.py)、[summary](../reports/biological_context/summary.md)。

### 事件：外部机制工具未覆盖全部样本，修正公平比较流程

- 情境与相关人员（S）：为回应baseline不足，我将OSTIR引入统一评测；全量输出后，原解析器因假定每行都有score而失败。
- 困难、冲突或不确定性：11,696个输入有24个构建没有可评分site；缺失既不是合法0，也不能只从OSTIR指标中删掉而保留其他模型全部测试行。
- 我的责任（T）：区分预测失败与低表达，并保证方法比较不因样本范围不同产生偏差。
- 我的行动（A）：检查缺失row ID及RBS来源；解析器允许显式缺失、仍拒绝重复/非正/非法score；保存缺失清单；所有方法改在共同11,672构建上比较；OSTIR量纲映射只在训练折拟合；记录独立Conda环境与ViennaRNA版本警告。
- 为什么这样决策：外部机制模型与统计模型目标和数值尺度不同，必须统一输入、行集与评估口径；软件论文也显示RNA能量引擎及参数变化会影响模型实现，因此版本记录有价值。参考：[OSTIR软件论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC9518832/)。
- 结果（R）：全量机制对照闭环，可评分覆盖率99.7948%；形成可追踪缺失处理和共同样本协议；结果支持单组留出B6优于OSTIR，双新不能判胜。
- 复盘、改进或后续变化：共同完整案例分析可能对缺失组产生选择边界，仍需对24行单独描述；OSTIR1.1.1/ViennaRNA2.7.2版本组合需保留提示，未做严格版本敏感性复现。
- 可体现的能力：第三方科研工具集成、异常定位、公平benchmark、缺失数据处理、环境复现。证据：[阶段4](biological_modeling_stage_log.md)、[OSTIR runner](../scripts/run_ostir_baseline.py)、[metadata](../reports/biological_context/ostir_run_metadata.json)。

### 事件：定位折叠计算瓶颈，并保持测试与仓库数据隔离

- 情境与相关人员（S）：加入RNA ensemble计算后，模型集成测试对全数据重复折叠，147秒仍未进入有效测试结果。
- 困难、冲突或不确定性：生物计算成本集中在特征预处理；环境默认pytest capture还有段错误；旧结构算法某些长区段产生0且与独立数值检查不符。
- 我的责任（T）：建立可迭代、能发现数值错误、不会覆盖正式数据的验证流程。
- 我的行动（A）：将600行固定smoke用于API调用链；全量benchmark单独预计算；缓存特征矩阵；管线/模型测试输出到pytest临时目录；使用`-p no:capture`规避已记录环境故障；废弃错误数值输出，用硬约束PF差和指定构建数值区间复核。
- 为什么这样决策：将接口可用性、数值正确性和全量科学效果分别验证；小样本smoke负责快速回归，全量评测保留正式结论，避免用缩小测试的数据夸大模型效果。
- 结果（R）：特征预计算日志约3–4分钟；阶段2记录44项全仓测试通过，后续阶段9为64项通过；没有受控对比足以宣称提速倍数。
- 复盘、改进或后续变化：缓存依赖文件版本而非完整实验配置，换CDS/折叠参数应重新计算；后续可做批量预测与模型单次加载，测量真正时延收益。
- 可体现的能力：性能定位、科学计算数值验证、回归测试隔离、取舍判断。证据：[阶段2/4](biological_modeling_stage_log.md)、[缓存实现](../modules/model/model.py)、[数值回归测试](../tests/test_features.py)。

### 事件：将“重要性图”和预测区间改为有明确含义的输出

- 情境与相关人员（S）：模型需要解释结构特征贡献；初次采用逐行置换，接口还存在点预测±25%的`confidence_interval`占位字段。
- 困难、冲突或不确定性：逐行置换破坏同一生物实体内的特征恒定性；固定百分比没有统计校准，容易被误解为可靠预测区间。
- 我的责任（T）：确保分析和用户输出的含义与计算过程一致。
- 我的行动（A）：作废逐行置换探索结果，按promoter/RBS/pair实体联合置换特征块；增加单位内一致性与聚合测试；保存OOF失败案例；移除伪区间并同步schema/说明/测试，保留真实评测bootstrap CI。
- 为什么这样决策：解释结果首先服务判断模型依赖与失效边界；对科学含义不明确的字段，先减少输出，再设计校准实验。
- 结果（R）：正式3,600条置换记录揭示结构组在严格留出中有补充价值；400条误差记录支持后续复查；API返回点预测、特征和上下文状态。
- 复盘、改进或后续变化：置换重要性不等于因果效应；未来若提供单预测区间，需要独立校准集并报告覆盖率和区间宽度。
- 可体现的能力：模型解释、科学产品判断、测试契约维护、可信输出设计。证据：[阶段6/7/9](biological_modeling_stage_log.md)、[置换实现](../scripts/grouped_feature_group_permutation.py)、[预测schema](../modules/model/predict_expression.json)。

## 8. 领域专属补充

- 研究对象、物种、队列或样本：大肠杆菌调控元件组合；本地有效构建11,696，非11,696位患者或独立生物重复。原论文实验宿主为MG1655、pGERC/sfGFP体系；培养方法记载30°C、LB–Miller，属于原作者实验背景。参考：[Kosuri原论文方法](https://pmc.ncbi.nlm.nih.gov/articles/PMC3752251/)。

- 数据规模与质量控制：112 promoter、111 RBS；11,696组合；沿用作者bad.prot/bad.RNA过滤，另做ID关联和序列检查。TSS_best范围−29…−4 nt；TSS_pct_best约0.165…0.978，未见按其置信度门限过滤或分层评测。
- 参考基因组、注释或数据库版本：未使用全基因组比对参考/Ensembl注释；关键参考是Kosuri2013补充数据、Addgene#47441记录和Gilliot论文来源的暂定90nt sfGFP FASTA。精确实验质粒逐碱基一致性未证实，访问路线已按现有记录跳过。
- 统计方法与多重检验：自然对数目标、Spearman、log-MAE、R²；组/交叉cluster bootstrap；五折与多seed描述性汇总；特征组置换及边际eta²。未见差异表达、多重检验FDR或因果识别分析，不补写这些经历。
- 生物学解释与验证边界：`prot/RNA`为稳态proxy，包含蛋白积累/降解及RNA稳定性影响，非纯瞬时翻译速率；仅固定sfGFP早期CDS背景，未验证任意CDS/菌种。ViennaRNA计算37°C与原实验30°C不同，尚无温度敏感性对照。

### 机器学习

- 任务定义：端到端蛋白表达回归；辅助转录水平与翻译proxy回归；产品对候选RBS做回归值排序。
- 数据集、标注与划分：原实验标签复用；主grouped比较11,672共同样本；随机行、新promoter、新RBS、双新场景分别报告；双新外折只取两类留出交集，训练排除任一测试ID。
- 模型与训练策略：9/10/12维工程特征XGBoost；同特征StandardScaler+Ridge内层调参；元件效应baseline与外部OSTIR。没有自监督预训练、Transformer微调、embedding或LoRA证据。
- 指标、基线、消融：Spearman/log-MAE/R²；B4→B6检查结构贡献，B3检验历史结构假设，Ridge检验非线性模型选择；top-k命中、Kendall、top-1 regret虽在路线图提出，未见已完成结果。
- 错误分析、公平性与泛化边界：按元件/目标分位定位残差，保留salis-3-3等失败；这里的公平比较主要是相同行集/拆分/调参权限，并非人群公平性评估。外部实验验证、跨CDS、跨宿主、无TSS推理均未完成。
- 推理或部署条件：本地Python环境、兼容的可信模型pickle、promoter+RBS输入；完整结构特征需TSS和ViennaRNA。当前无模型文件可直接部署；benchmark模型与原尺度API模型区分，尚无线上运行或监控记录。

### LLM 工具调用与科研工作流

- 编排方式：一个Gemini客户端维护进程内对话history，按模型function_calls调用本地MCP，再将结果加入上下文；没有多Agent角色、路由器、共享记忆或自治协作评测。
- 工具、模型与权限边界：12个MCP工具包含读计算与数据构建写文件工具；当前无工具级权限分层、人工审批网关或持久审计。该写工具是项目本身的能力，本次素材采集未调用。
- 人工审核/介入点：人选择序列与请求，专家反馈推动模型改进；未见每次预测后的自动人工审核或湿实验执行流程。
- 评估集、成功率、成本、时延：预测模型有正式基准；LLM工具选择只有文档示例/注册烟测，没有固定问答任务集或端到端成功率，不移用模型ρ作为Agent成功率。
- 失败恢复、可观测性与安全机制：工具异常回传error；429/503最多3次尝试，退避/读取retry提示；控制台打印调用和结果。未见轮数上限、超时预算、持久checkpoint、结构化trace、提示注入测试；客户端的resource-name解析说明也未见server对应实现，端到端支持待核对。

## 9. 可复用方法

### 方法：生物数据语义先行的特征工程

- 实际使用场景：修正promoter-tail MFE与真实转录本不一致的问题。
- 操作步骤：阅读原字段说明 → 确认TSS/序列边界与参考来源 → 建立坐标/字母表契约 → 手工序列测试 → 用机制对应特征替换粗略代理 → 同条件消融检查收益。
- 适用边界：需要可信测量坐标或参考；暂定序列可以支持方法开发，不能自动支持跨上下文生物结论。
- 对应证据：数据字典、上下文函数、阶段1–3、B4/B6结果。

### 方法：交叉生物实体的无泄漏验证

- 实际使用场景：启动子×RBS组合矩阵中的新元件泛化评估。
- 操作步骤：识别重复实体 → 分别冻结两类ID折 → 训练排除任一留出ID → 测试取交集 → 记录unused边 → 共用预测行比较 → 组bootstrap → 多seed方向检查。
- 适用边界：五折paired-diagonal双新方案只测试一部分组合；同数据bootstrap/多seed不代替独立外部验证。可迁移到药物×靶点等交叉实体问题，但该迁移未在本项目实际实施。
- 对应证据：grouped validation、split tests、fold assignment、multiseed结果。

### 方法：同条件基线、消融和失败组诊断

- 实际使用场景：区分新增结构特征收益、算法收益和数据切分难度。
- 操作步骤：统一输入与目标 → 冻结共同样本/外折 → 只在训练内调参/校准 → 比较B4/B3/B6/Ridge/OSTIR → 按组联合置换 → 按相同OOF行配对残差 → 展示极端失败而非仅最高分。
- 适用边界：特征组置换说明模型依赖，非因果；oracle不代表未知序列部署能力。
- 对应证据：baseline scripts、permutation、OOF diagnostics及summary。

### 方法：将科研模型封装为可解释 LLM 工具

- 实际使用场景：自然语言请求触发序列解读、预测和RBS筛选。
- 操作步骤：定义确定性函数 → JSON描述输入输出 → 动态MCP注册 → 客户端发现并转换schema → 工具调用/异常回传 → 返回点预测、特征和上下文状态。
- 适用边界：仅支持当前单LLM调用模式；需要另外评估输入校验、工具权限、轮数预算、TSS缺失和模型工件版本，才能走向可靠部署。
- 对应证据：server、client、JSON wrappers、模型测试与阶段9。

### 最高信息增益问题（12 个）

1. **2026年5月交付版本具体包含哪些功能和指标，9–10月补强是否也由你参与？** 有无5月报告/演示/截图可恢复主体周期的成果边界？这能确定哪些强数字可放在同一项目日期下。
2. **BioE234与你的正式关系是什么？** 是修课、访学期间课程、参考公开课程还是其他；有没有评分/结课材料？这能决定是否保留课程组织背景。
3. **你最初为什么选这个项目，想支持哪种具体使用场景？** 学习、合成生物实验、研究兴趣或导师需求；回答可强化项目立项与个人判断。
4. **哪些模块由你从零开发，哪些来自course starter、同学或AI辅助？** 尤其Gemini客户端、server、模型/验证脚本；回答可形成准确且有力的个人贡献边界。
5. **教授最关键的原话是什么，你实际怎样回应，后续是否收到认可或评分变化？** 可补充反馈闭环的真实互动与结果，而非仅代码状态。
6. **是否有真实使用者或你完成过的完整自然语言演示？** 最好提供典型输入、工具链、输出及失败情况；可建立应用可用性而非工具数量的证据。
7. **是否曾保存或运行全量训练的模型，模型文件现在哪里，最终训练目标是哪种？** 当前artifacts为空；答案可衔接benchmark成果与实际产品预测。
8. **有没有根据RBS排名实际合成/测量候选，或获得实验方反馈？** 对照、样本数、单位和测试条件是什么；可把潜在筛选价值转为实际业务/研究结果。
9. **你当时最困难的一次排错或取舍是哪件，如何独立发现、判断和解决？** 可补充STAR中的真实个人思考，避免只用阶段日志描述过程。
10. **是否有运行硬件、训练/推理时间、工时或API费用记录？** 可验证性能、资源取舍和独立交付效率，支撑工程岗位表达。
11. **对30°C原实验与37°C结构计算、低TSS置信度、缺TSS输入或高误差RBS，是否做过未收录的检查？** 可揭示现有仓库之外的稳健性证据和真正的领域判断。
12. **已有外部数据/跨CDS验证、top-k/regret评测或后续实验计划吗？职业经理人优先服务哪类岗位？** 可决定继续挖掘顺序，并将同一证据适配AI应用、生信或研发数字化表达。
